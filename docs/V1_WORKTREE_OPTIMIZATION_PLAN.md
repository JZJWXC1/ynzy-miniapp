## 择优合并策略

1. 先合并低冲突、高确定性的导航分支。
2. 再合并上传契约分支，确认标签前后端一致。
3. 合并地图分支时保留小区聚合与真实坐标约束；若与后端核心契约冲突，以后端 P0 规则为准。
4. 合并助手分支时保留“识别 -> 确认 -> 匹配/追问”链路，并补充敏感信息脱敏检查。
5. 最后合并后端核心契约分支，解决全链路 P0；如果与地图后端文件冲突，人工保留两边必要行为。

## 合并准入条件

每个子工作树合并前必须提供：

- 修改文件清单。
- 接口变化说明。
- 数据结构变化说明。
- 测试结果。
- 未解决问题。
- 微信开发者工具验收步骤。
- `git diff --name-only` 越界检查结果。

任何分支出现以下情况，不进入合并工作树：

- 修改 `server/scripts/smoke-test.js`。
- 引入房源群、积分、充值、换群、微信支付等第一版隐藏入口。
- 地图使用随机坐标、散列坐标、估算坐标或默认中心点冒充真实位置。
- 前端可提交或展示可编辑分佣比例。
- 后端信任客户端 `brokerId/uploaderId/commissionRate`。
- 日志输出完整客户手机号、房东电话、微信号或身份证。

## 合并后总审计

合并工作树完成集成后，必须重新审计：

1. 底部导航是否固定为找房、房源、地图、我的。
2. 地图是否只展示真实确认小区坐标，且按小区显示房源套数。
3. 找房助手是否能准确识别需求、追问、字段确认，并支持筛选后进入地图/列表。
4. 上传是否强制视频，标签是否能被后端接受。
5. 前台列表、地图、助手是否只展示有效且符合第一版规则的房源。
6. 房态是否第 3 天提醒、第 5 天再提醒、第 7 天自动失效。
7. 报备是否客户称呼可选、手机号必填。
8. 签单是否只能从报备发起，且只填写成交月租、房东实际支付佣金、备注。
9. 管理员确认签单后是否生成上传人 20% 分佣记录，金额是否按分存储。
10. 是否仍存在积分、充值、换群、微信支付、房源群入口或文案。
