# 打包与脱敏清单（任何外发 ZIP 必读）

> 背景：2026-07-02 的审计瘦身包虽然剔除了 `server/.env`，但把 **微信支付商户 API 私钥**
> （`server/certs/apiclient_key.pem`，商户号 1746601037）和含真实中介手机号的
> `server/data/db.json` 一并打了进去，并通过微信文件传输外发。本清单用于杜绝复发。

## 一、事故处置（立即执行，只需一次）

1. 登录微信商户平台 → 账户中心 → API 安全 → **作废当前 API 证书并重新申请**，
   替换服务器上的 `server/certs/` 后重启服务。
2. 如 APIv3 密钥曾出现在任何外发文件中，一并重置。
3. 通知收到过旧审计包的人删除文件。

## 二、外发/审计打包必须剔除的路径

任何要发给外部（包括发给 AI 审计、发到微信群）的源码包，除 `node_modules`、
构建产物、`.git` 外，**必须额外剔除以下内容**：

- `server/.env` 及一切 `.env.*`（现有脚本已覆盖）
- `server/certs/`（微信支付商户证书与私钥，本次事故泄露点）
- `server/data/`（db.json 含真实中介/管理员手机号）
- `project.private.config.json`（个人 IDE 私有配置）
- `lark-*.json`（飞书表格/文件夹 token）
- `server/server.log`、`server/server.err.log` 等日志

判定原则：**`.gitignore` 里出现过的路径，外发包一律不带**。瘦身脚本应直接读取
`.gitignore` 生成剔除名单，而不是维护第二份清单。

## 三、部署包（package-deploy.ps1）的默认行为

- `server/.env` 及一切 `.env.*`：默认不打包；上线部署包不得携带。
- `server/data/`：**本次已改为默认不打包**，首次部署需要种子数据时显式加
  `-IncludeData`，并把生成的 ZIP 按敏感文件管理。
- `server/certs/`：部署脚本从不打包；证书只允许通过服务器上手工放置。

## 四、上线前自查命令

```bash
# 在待外发的 ZIP 上执行，任何一行有输出即打包失败
unzip -l 外发包.zip | grep -Ei "certs/|\\.env|server/data/|private\\.config|lark-.*\\.json|\\.pem"
```
