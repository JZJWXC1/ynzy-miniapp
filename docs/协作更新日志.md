1. 本文是项目当前唯一主协作更新日志。新消息写在“最新进展”顶部，不删除历史；口径变化要写“作废原因”和新口径。

让中介可以稳定完成“浏览真实房源 -> 查看受控敏感信息 -> 一键联系房东 -> 收藏和再次筛选 -> 查看附近可替代房源”的完整工作流，同时让佣金口径清晰、敏感操作可追踪、旧客户端不能绕过暂停功能、登录状态稳定，并保持服务端权限与分佣计算不可由客户端操控。

- 房源特点新增 `Loft`、`落地窗`，与服务端白名单、筛选、推荐资料和编辑回显保持一致。
- 新增可空房源备注，最多 200 字；服务端拦截手机号、微信号等联系方式，防止绕过敏感信息保护。
- 房东手机号对公司、业主、二房东房源及所有看房方式均为必填；存量缺失时详情显示待补充且不提供拨号，编辑时必须补齐。
- 新增必填字段“房东佣金占月租比例”，只允许 `0` 至 `100` 的整数，默认 `50`。
- 所有缺失新佣金字段的存量房源迁移为 `50%`；迁移前备份，迁移前后只核对房源总数与字段覆盖率，不在本文记录真实房源内容。

### G2 详情页与佣金明细

- 删除详情顶部旧佣金条，删除上传人显示，压缩城市、区域、小区、楼栋、单元、房间号布局。

- 新增佣金明细：房东总佣金、带看人、房源维护人、平台服务费，全部显示为占月租比例。
- 业主/二房东房源按服务端当前拆分计算：带看人取得房东佣金的 70%，维护人 20%，平台 10%。房东佣金为月租 50% 时，对应月租 35% / 10% / 5%。
- 公司房源也必须填写房东佣金比例；带看人取得全部该佣金，维护人与平台为 0%。
- 签单恢复后，房东实付佣金必须由“成交月租 x 房源佣金比例”自动计算并锁定，不能由客户端手填金额。
- 分佣比例、当前用户身份、维护人身份和最终金额均由服务端计算；客户端提交同名字段必须忽略或拒绝。

### G3 暂停客户报备与敏感信息监管

- 小程序移除客户报备、我的报备、报备签单和相关引导；服务端拒绝旧版本新增报备及从报备新增签单。
- 历史报备、签单、分佣数据保留，后台继续只读查询；暂停功能使用可恢复开关，不物理删除历史代码和数据。
- 查看别人上传的业主/二房东房源时，取消绑定需求单和填写用途，只保留已开通账号、二次确认、每日查看额度及服务端足迹。
- 自己上传的房源继续免留痕直接查看；公司房源直接展示基础联系信息，但点击拨号必须留痕。
- 保留“拍水印照片记录带看”及审核换额度能力。
- 足迹只记录操作者、房源、服务端时间、动作类型和幂等标识，不记录地址、电话号码或完整房源内容。

### G4 一键联系房东

- 获取敏感信息后显示“联系房东”，调用微信拨号能力；公司房源使用服务器环境配置的默认联系电话，不在仓库硬编码真实号码。
- “电话查看”只统计实际成功打开系统拨号页的行为，不能把“看到电话号码”误算为拨号。
- 拨号足迹必须可幂等补记；网络失败不能制造重复记录，也不能把号码写入日志、错误消息或分析事件。

### G5 附近三公里推荐

- 全部来源的有效在租房源参与计算，排除当前房源、待审、下架、过期和已成交房源。
- 只使用可靠坐标；按距离由近到远，详情页最多展示 6 套，超过时提供“查看全部附近房源”。
- 卡片展示距离、房源类型、户型、特点和租金；无可靠坐标或无结果时不渲染误导性空板块。
- 游客只获得其原本有权限查看的房源；不能借附近推荐泄露合作房源。

### G6 收藏与我的收藏

- 收藏绑定服务端中介账号，多设备同步；未登录点击星标时引导登录，不保存匿名本地收藏。

- 我的收藏支持区域、板块、小区、户型、整租/合租、租金区间、房源特点、可用状态及公司/业主/二房东类型筛选。
- 下架、过期或成交房源继续以灰色“暂不可用”状态保留，可取消收藏，但不能继续敏感信息操作。

### G7 足迹、FAQ 与登录保持

- 足迹页保留顶部四个统计方块；下方筛选只保留“我的房源被查看”和“电话查看”，默认进入“我的房源被查看”。

## 禁止重踩的坑

1. **不要复用旧 `commissionRate` 表达“佣金占月租比例”**：旧字段表达上传人/分佣配置语义。新字段必须使用清晰独立名称，避免迁移后把 20% 错当房东总佣金。
2. **不要把页面显示写死成 35/10/5**：它们只在房东佣金为月租 50%、拆分为 70/20/10 时成立；页面必须由服务端返回的总佣金与拆分计算。
3. **不要信任客户端分佣、身份或维护人字段**：客户端只能提交允许的房源业务输入；服务端从已验签账号、房源来源和配置计算结果。
4. **不要只隐藏报备按钮**：旧体验版仍可能调用接口。服务端新增报备和报备签单必须同步关闭，历史读取保持。
5. **不要在第 7 天删除足迹**：7 天是中介端展示窗口，后台证据保留 90 天。
6. **不要把“看见电话号码”算作电话查看**：只有系统拨号页成功打开才计入；拨号取消或 API 失败不能记成功。
7. **不要记录电话和地址正文**：足迹、错误日志、请求日志、埋点、测试输出和本文都只使用 ID、动作与脱敏事实。
8. **不要硬编码公司联系电话**：生产号码只从服务器环境配置读取；测试使用明显假值。
9. **不要用不可靠坐标做 3 公里推荐**：缺坐标、默认中心、未验证手填坐标都不能进入距离计算。
10. **不要让星标点击冒泡打开详情**：卡片星标必须阻止事件冒泡，并处理快速重复点击与失败回滚。
11. **不要只保存 userId 当登录态**：请求必须使用有效签名 token；30 天续期不能绕过 tokenVersion、改密和停用撤销。
12. **不要直接在当前历史工作树开发**：它落后于最新主线且有他人未提交记录。必须从最新 `origin/v1-broker` 建新工作树。
13. **不要用肉眼扫最新几条 log 判断提交是否已落地**：用祖先关系和精确 commit 校验，避免把已经合入的提交再次 cherry-pick。
14. **不要从未经审计的 HEAD 打包**：发布前锁定拟发布 commit；打包、push、部署和健康回显必须指向同一提交。
15. **不要让文档先于真实状态**：未运行的测试不能写通过，未成功的 push/部署不能写完成，失败也必须如实记录。
