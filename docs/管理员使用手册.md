## 1. 后台是做什么的 · 如何登录

后台叫**"内部房源协作管理后台"**，用来**审核小程序注册申请、查看全公司房源、敏感信息查看足迹、报备记录、签单审核和分佣记录**，以及管理账号、配置找房助手、同步飞书房源等。

### 登录步骤

1. 用浏览器打开后台地址（形如 `你们的后端地址/admin-web/`，具体地址向技术/运维索取）。
2. 页面显示**"管理员登录"**，副标题"管理员账号由后端校验。请使用已配置的正式管理员账号。"
3. 输入**"账号"**和**"密码"**（由超级管理员分配，本手册不写具体账号密码）。
4. 点**"进入后台"**。

**你会看到什么：** 登录成功后进入后台主界面，右上角显示"管理员：你的账号"。左侧是分组菜单。

**登录失败常见提示：**
- "请输入账号和密码。"——账号或密码为空。
- "账号或密码错误，或无管理员权限。"——账号密码不对，或该账号无后台权限/已被禁用。

> 登录状态保持 8 小时，过期后重新登录即可。

## 2. 权限说明：超级管理员和普通管理员（先读）

后台管理员分两档，**看到的菜单不一样**：

| | 超级管理员 | 普通管理员（受限权限） |
| --- | --- | --- |
| 判定方式 | 账号权限为"全部后台权限"（老账号未标权限的也按超管处理） | 账号被显式标为"区域查看权限"或"后台查看权限" |
| 运营看板 / 成交闭环 / 风控记录 | 可见可操作 | 可见可操作 |
| **系统配置整组**（飞书同步、LLM配置、客服反馈、客服Trace、上线检查、账号管理、数据备份） | 可见可操作 | **整组隐藏，接口也会拒绝（403）** |
| 分佣配置卡片（房源管理页顶部） | 可见可改 | 不可见 |
| 注册审核、给中介设/重置密码、建号、停用/删除账号 | 可操作 | 不可操作 |

几个要点：

1. **注册审核、账号管理、分佣配置等"动账号、动钱规则"的操作都只有超级管理员能做**。这不只是前端把菜单藏起来，后端接口同样校验，普通管理员调用会直接被拒绝。
2. **"账号管理"里既有后台管理员账号，也有中介/员工账号**：管理员账号行可以改密码、启用/禁用、删除；中介/员工行可以设置/重置登录密码、删除（详见第 5、6 节）。
3. **分佣比例现在可以在后台改**（超管专属，见[第 13 节](#13-签单确认与分佣含分佣配置)），改动只影响之后的新签单——已提交的签单按签单当时的配置快照结算。

## 4. 注册审核 SOP（开通中介账号）★新流程

小程序端已改为**"注册申请—管理员审核—开通"**：中介在小程序提交姓名、手机号和自设密码后，申请进入后台待审核列表；**你审核通过，账号才开通，对方才能登录**。这是管理员最常做的动作之一，请按下面的 SOP 走。

### 4.1 在哪里看待审核列表

**菜单：系统配置 → 账号管理**，页面下半部有**"注册审核"**卡片（仅超级管理员可见）。

- 说明文字："小程序注册申请先进入待审核列表，管理员审核通过后才开通账号；通过时选择开通为中介或员工，驳回可留原因。"
- 表格列：**姓名、手机号、申请时间、状态、操作**。
- 状态为"待审核"的行，操作列有三个按钮：**"通过为中介" / "通过为员工" / "驳回"**。
- 没有申请时显示"暂无注册申请"。可点**"刷新申请"**手动刷新。

### 4.2 审核 SOP（逐条走）

1. **核实身份**：看姓名和手机号，确认这个人确实是要合作的中介或自己公司的员工。拿不准就先打电话或问业务负责人，**不认识的号码不要随手通过**。
2. **选对类型再通过**：
   - 外部合作中介 → 点**"通过为中介"**（有敏感信息查看额度：业主 3 套/天、普通 15 套/天）。
   - 自己公司内部员工 → 点**"通过为员工"**（内部上传、带看用）。
   - 点了会弹确认框"确认通过该注册申请，开通为中介/员工账号？"，确认后提示"已通过并开通账号"。
3. **通知本人可登录**：通过后**对方注册时自己设的密码直接生效**，你只需要通知他"账号已开通，用注册时的手机号和密码登录小程序"。**不需要**再帮他设密码。
4. **驳回要留原因**：不该开通的申请点**"驳回"**，会弹输入框"请输入驳回原因（可留空）"——**请尽量填写原因**（如"身份未核实""非合作对象"），原因会显示在申请记录里，方便日后复盘，对方重新申请时也有据可查。

### 4.3 几个细节

- 同一手机号重复提交申请不会产生重复记录，只会刷新姓名/密码/时间。
- 被驳回的人可以重新提交申请，状态会重置为"待审核"。
- 已开通的手机号再去注册，小程序会直接引导他登录，不会进你的待审核列表。
- 审核通过后，该账号会出现在上方账号表的中介/员工行里。

## 5. 给中介/员工设置或重置登录密码 ★新流程

小程序登录已是**手机号 + 密码**制，没有密码的账号一律无法登录。以下三种情况都由你在后台发密码：

1. **老账号**（密码改造前就存在的中介）第一次要登录；
2. **后台直接建的账号**（建号时没填初始密码）；
3. **中介忘记密码**要求重置。

### 操作步骤（仅超级管理员）

1. **菜单：系统配置 → 账号管理**，在账号表里找到该中介/员工的行（可看姓名、手机号）。
2. 点操作列的**"设置密码"**（从没设过密码）或**"重置密码"**（已有密码）。
3. 弹出输入框"请输入 ×× 的登录密码，至少 8 位（设置后请转告本人，本人登录后可自行修改）"。
4. 输入一个**至少 8 位、不含空格**的初始密码，确定。
5. 提示"登录密码已设置，请妥善转告本人。"

**转告时提醒对方两件事：** 用手机号 + 这个初始密码登录；登录后到"我的 → 修改密码"改成自己的密码。

> 注意：后台**看不到**任何人的现有密码（密码加密存储），只能重置成新的。中介自己记得原密码时，可以在小程序里自助修改，不用找你。

## 6. 账号管理：新建 / 停用 / 删除

**菜单：系统配置 → 账号管理**（仅超级管理员可见）。

### 6.1 账号表怎么看

表列：**账号、姓名、权限、今日查看、状态、操作**。表里有两类行：

- **后台管理员账号行**：操作列有**"修改密码"**（弹窗填新密码，至少 8 位）、**"启用/禁用"**（二次确认）、**"删除"**（不能删当前登录的自己）。
- **中介/员工行**：操作列有**"设置/重置密码"**和**"删除"**。"今日查看"显示当天额度用量（如"业主 X/3 · 普通 Y/15"），"权限"列显示其角色。

### 6.2 新增账号（三种类型）

**"新增后台账号"**表单，先选**类型**：

| 类型 | 用途 | 要填什么 |
| --- | --- | --- |
| **管理账号** | 登录这个后台 | 可绑定员工、账号（3-24 位字母数字）、姓名、初始密码（至少 8 位）、权限（全部后台权限 / 区域查看权限 / 后台查看权限） |
| **中介账号** | 小程序登录，外部合作中介 | 姓名、11 位手机号，**初始密码可填可不填** |
| **员工账号** | 小程序登录，内部员工 | 姓名、11 位手机号，**初始密码可填可不填** |

填好点**"创建管理员账号"**。要点：

- 建中介/员工账号时**建议顺手填上初始密码**，对方马上就能登录；不填的话账号建好也登不了，还得回来点"设置密码"补一次。
- 管理账号的权限选"全部后台权限"即超级管理员；选"区域查看权限"或"后台查看权限"则是普通管理员，看不到系统配置整组。
- 密码至少 8 位，不能用内测默认弱密码；所有密码都加密保存。
- 同一手机号已有账号时会被拦截，不会重复建号。

### 6.3 停用与删除

- **停用后台管理员**：管理员行点**"禁用"**（二次确认），被禁用的账号无法再登录后台；要恢复点"启用"。不能禁用自己。
- **删除后台管理员**：管理员行点**"删除"**，确认"删除后该账号将无法登录（软删归档、保留操作留痕）"。
- **删除中介/员工**：中介/员工行点**"删除"**，确认"删除后该账号将无法登录（软删归档，其名下房源/成交/分佣历史数据保留）"。删除后此人登录会提示"手机号未开通"。
- **恢复合作怎么办**：删除是软删，历史数据都在。对方重新提交注册申请、你在注册审核里通过，或直接在后台重新建号即可，名下历史数据不受影响。

> 中介问"我的账号是不是被停了"：中介账号没有单独的"禁用"按钮，被删除（软删）即无法登录。先在账号表确认他的行还在不在，再决定是重新开通还是维持现状。

## 7. 数据总览

**菜单：运营看板 → 数据总览**（只读，无操作按钮）。

顶部 6 个统计卡：

- **待维护房源**
- **即将失效 / 废房源池**（"第 7 天自动进入资产池"）
- **待跟进报备**（未发起签单或待补充）
- **待确认签单**（管理员确认后生成分佣）
- **今日敏感查看**（需复盘的次数）
- **待确认预计上传人分佣**（金额，后端按规则拆分）

下方左侧是**"区域房源数量"**，右侧是**"风险提醒"**表，把上面几类待办用色块标出状态。

**日常用法：** 每天上班先看这里，重点盯"待确认签单""今日敏感查看""即将失效"，安排当天要处理的审核和核验。

## 8. 房源管理（编辑 / 电话核验 / 下架）

**菜单：运营看板 → 房源管理**。

### 8.1 页面顶部两张配置卡

1. **"上传房源电话核验规则"**：说明固定为"第 3 天提醒上传人核验，第 5 天再次提醒，第 7 天未更新自动失效并进入后台资产池"。开关只控制**第 3、5 天要不要提醒**；**第 7 天自动失效是固定规则、始终生效**。改完点"保存规则开关"。
2. **"分佣配置"**（仅超管可见）：见[第 13 节](#13-签单确认与分佣含分佣配置)。

### 8.2 筛选与表格

- **筛选**：区域、板块、来源（公司/业主/二房东）、状态（在租/待确认/待审核/已驳回/已签单成交）、小区名称等。
- **表格列**：房源、区域、板块、小区名称、上传人、租金、户型、分佣、视频、状态、房态、操作。
- 房态列还会显示**坐标状态**：坐标不可靠的房源会亮**"⚠ 坐标待修正"**红标，提醒你去修坐标（见[第 10 节](#10-坐标修正让房源上地图)）。

### 8.3 操作列 5 个按钮

| 按钮 | 作用 |
| --- | --- |
| **编辑** | 打开编辑弹窗，可改位置、户型、租金、联系方式、特点标签、状态等。**修改后立即生效**。 |
| **电话核验** | 只有到期需要核验的房源可点。二次确认"确认已电话联系房东，并确认这套房源仍可出租？"确认后更新房态核验时间。 |
| **坐标修正** | 打开地图点选弹窗修正房源位置（见第 10 节）。坐标待修正的房源此按钮会带 ⚠。 |
| **审核通过 / 驳回** | 只有"待审核"房源可点，与"房源审核"菜单等效。 |

### 8.4 手动下架

在**"编辑"**弹窗里把**状态改为"已下架"**并保存，房源会立即**移入后台资产池（废房源池）**，之后可在资产池重新上架。审核与成交状态不要用编辑硬改，走对应的审核/签单流程。

## 9. 房源审核（业主/小区未匹配房源上架）

**菜单：运营看板 → 房源审核**。

顶部说明："只显示业主房源、小区未匹配或其他需要人工确认的待审核房源。审核通过后才会进入前台有效房源；驳回后不会对中介展示。"

### 操作步骤

1. 列表里点某套待审核房源进入详情。
2. 详情页可以**看视频**、看标签，以及一整屏只读字段（来源类型、审核原因、小区匹配、租金、户型、完整地址、房东电话、上传人、视频状态、分佣规则等），还能展开"查看完整原始字段"。
3. 核对无误后点**"审核通过"**（二次确认后上架）；或点**"驳回"**（二次确认后不上架）。
4. 点**"返回列表"**回到审核列表。

- 常见审核原因："小区名称未匹配，需要管理员确认""业主房源需要管理员审核"。
- 审核通过后建议顺手看一眼该房源的坐标状态，未匹配小区的房源往往需要**坐标修正**才能上地图。

## 10. 坐标修正（让房源上地图）

小程序地图页按小区展示房源，**坐标不可靠的房源上不了图或位置不准**。系统会自动地理编码，编码失败或只兜到板块中心的房源会在房源管理里亮"⚠ 坐标待修正"。

### 操作步骤

1. **菜单：运营看板 → 房源管理**，找到带"⚠ 坐标待修正"的房源（或任意想校准的房源），点操作列**"坐标修正"**。
2. 弹出**"坐标修正"**窗口：**在地图上点击或拖动标记**，把标记放到房源真实位置（弹窗说明：确认后记为「已确认坐标(verified)」并上图）。
3. 选好后下方会显示"已选：纬度, 经度"，点**"确认坐标"**。
4. 成功提示**"坐标已修正为已确认坐标"**，该房源即以确认位置上图。

**没有地图怎么办：** 如果弹窗提示"未配置地图 JS-API key"或地图加载失败，可以在弹窗下方**手动输入经纬度**后点"确认坐标"（经纬度可从地图软件上查）。地图 key 配置属运维范畴，交给技术处理。

**巡检建议：** 每周过一遍房源管理里的"⚠ 坐标待修正"，逐套修正——坐标准了，中介地图找房才找得到这些房。

## 11. 废房源池（重新上架）

**菜单：运营看板 → 废房源池**。

顶部说明："后台资产池保留完整房源信息、视频和标签；重新上架前请核对视频、房态、地址和房东联系方式。"

- **表格列**：房源、状态/原因、小区、租金、户型、标签、视频、下架时间、操作。
- 进入资产池的三种来源：第 7 天未维护自动失效；中介电话确认时选了"已出租/不租了"；管理员编辑改为"已下架"或飞书同步下架。
- **操作**：点**"重新上架"**（二次确认"确认已核对房态，并将该房源从废房源池重新上架？"），房源恢复为在租。

**用法：** 当上传人已重新联系房东确认房源还在租，你核对视频和房态后，把它从废房源池"重新上架"。

## 12. 报备记录

**菜单：成交闭环 → 报备记录**（只读）。

顶部说明："报备客户称呼可选，客户手机号必填；后台只展示脱敏手机号，签单必须从报备记录发起。"

- **表格列**：报备房源、needId/快照、报备中介、客户、报备状态、签单记录、时间。
- 客户手机号**脱敏显示**；"签单记录"列显示"已发起：<签单号>"或"未发起"。

**用法：** 核对哪些客户已报备、哪些报备已进入签单流程。

## 13. 签单确认与分佣（含分佣配置）

### 13.1 签单确认（最核心动作之一）

**菜单：成交闭环 → 签单审核**。

- 顶部 3 个汇总：**待管理员确认 / 已确认签单 / 待确认预计上传人分佣**（金额）。
- **表格列**：成交房源、needId/快照、报备中介、客户、成交金额、上传人分佣、状态、备注/时间、操作。

**操作步骤：**

1. 核对该签单的成交金额、房源、报备中介、客户是否真实无误（有疑问先到"敏感查看足迹"和"报备记录"里交叉核对）。
2. 点**"确认签单"**，二次确认后提示"签单已确认，正式分佣记录已生成"。
3. 该房源标记为已成交，分佣记录出现在"分佣记录"菜单里；已确认的签单按钮置灰。

> **重点：管理员确认之前不会生成正式分佣记录，确认之后才生成。** 公司房源确认签单时不生成分佣记录（不分佣）。

### 13.2 分佣配置（仅超管）

**位置：运营看板 → 房源管理**，顶部**"分佣配置"**卡片。

- 可调四个比例：**二房东上传人比例、二房东平台比例、业主上传人比例、业主平台比例**（现行默认：上传人 20%（二房东/业主同）、平台 10%，即从房东实付佣金中共分出 30%，带看成交中介净留 70%；任一比例上限 100%，上传+平台合计不得超 100%）。
- 改完点**"保存分佣配置"**。
- **配置快照机制**：中介提交签单时会锁定当时的比例，**你之后改配置不影响已提交的签单**，只影响新签单。所以调整比例前先把"待管理员确认"的存量签单处理完，避免口径混乱。

### 13.3 分佣记录

**菜单：成交闭环 → 分佣记录**（只读）。

- **表格列**：成交房源、上传人、成交人、总比例、上传人比例、房东实付佣金、上传人分佣、平台留存、状态、时间。
- 金额都是确认签单后按签单时的配置快照算出来的（公司房源不分佣；管理员上传的房源上传人 0%、平台仍按配置抽成（默认 10%）；上传人=成交人的自传自带单全免不生成记录）。

## 14. 敏感查看足迹（风控）

**菜单：风控记录 → 敏感查看足迹**（只读）。

- **表格列**：查看人、房源、查看内容、需求/用途、上传人、同步状态、时间。
- 记录了每一次"查看房东电话/地址"的动作，用来复盘、防跳单、界定成交归属。

**用法：** 出现成交纠纷或怀疑跳单时，来这里查谁在什么时候、以什么用途、看了哪套房的敏感信息。

---

## 15. 带看审核（通过给额度奖励）

**菜单：风控记录 → 带看审核**。

- **表格列**：带看人、房源、水印照片、水印信息、奖励、审核状态、操作。"水印照片"列可点开看大图。
- **操作**：
  - **"通过"**：二次确认"确认水印照片真实有效，并给带看人当天普通房源查看额度 +1？"——通过后，该带看人**当天普通房源查看额度 +1**。
  - **"驳回"**：二次确认后驳回。

**审核要点：** 重点核验照片是否为**现场真实拍摄、带时间和地点水印**。真实有效才通过——这是中介多拿查看额度的唯一途径，也是防止刷额度的关卡。

---

## 16. 飞书房源同步

**菜单：系统配置 → 飞书同步**（仅超管）。

- 有"飞书房源同步"和"最近结果"两块，按钮**"立即同步"**和**"预演同步"**。
- 说明："房源表为最终状态源；素材库按房号匹配视频。飞书下架或房源表删除会进入废房源池，缺素材会在后台标记'缺视频素材'。"
- 点"立即同步"会二次确认后按飞书房源表和素材库同步小程序公司房源。

**用法：** 公司房源来自飞书房源表。日常可点"立即同步"手动刷新；不确定影响时先"预演同步"看看结果。（服务启动后一般也会按配置周期自动同步，无需频繁手动点。）

## 17. LLM 配置 · 客服反馈 · 客服 Trace

（三项均在**系统配置**组，仅超管可见。）

### 17.1 LLM 配置（找房助手大模型）

- 表单字段：模型供应商、接口协议、API Base URL、各场景模型、密钥保存名、系统提示词。
- 按钮：**"保存配置"**、**"测试连接"**、**"恢复默认"**。
- **真正的密钥由技术在服务器环境变量里配置，本页只填保存名，不填明文密钥。** 改完用"测试连接"发一句测试需求验证。

### 17.2 客服反馈（找房助手推荐反馈）

- 中介在小程序推荐卡片上点"有用/不准"的反馈都汇总在这里。
- 可按状态筛选（待处理/已分诊/已加入评估/已解决/已忽略），操作按钮：**"分诊""解决""忽略""加入评估"**。
- 典型的坏推荐"加入评估"后沉淀成评估样本，用于以后回归测试助手效果。

### 17.3 客服 Trace（对话链路复盘）

- 只读。复盘找房助手每次对话的意图、槽位、工具输入输出、追问决策。
- 中介反馈"助手推荐不准"时：先在"客服反馈"看反馈 → 点它的 Trace 复盘当时的理解和决策 → 判断是否"加入评估"。

## 18. 上线检查 · 数据备份

### 18.1 上线检查

**菜单：系统配置 → 上线检查**（仅超管）。

- 顶部 3 个汇总：已通过 / 需处理 / 待人工确认。
- 下面列出各项自检卡片（如 OSS/RAM 最小权限、后台 Token 密钥、管理员初始密码、LLM 配房助手、微信合法域名等）。
- 底部有"缺失环境变量模板"和**"复制模板"**按钮。

**用法：** 上线前和大版本更新后对照这里逐项确认，"需处理"的项按提示交给技术处理。具体环境变量/密钥配置属于运维范畴，本手册不展开。

### 18.2 数据备份

**菜单：系统配置 → 数据备份**（仅超管）。

- **数据导出**：点**"导出 JSON 备份"**，下载一个 `ynzy-backup-日期.json` 文件。建议**上线前、批量导入前、每日下班前**各备份一次，备份文件内含用户数据，注意保密、不要外发。
- **异地备份 / 同步状态**：展示服务端加密异地备份的新鲜度、最近备份与恢复演练结果（只显示时间、文件名、成功与否，不含密钥）。发现备份长时间未更新（过期告警）及时找技术处理。

## 19. 日常巡检建议（每日照着做）

建议把下面这张清单当每天的例行动作（一共十来分钟）：

| 频次 | 看哪里 | 做什么 |
| --- | --- | --- |
| **每天上班** | 账号管理 → **注册审核** | 处理待审核注册申请：核身份 → 通过为中介/员工 → 通知本人可登录；不该开的驳回并填原因。**申请别积压**——对方在等着登录。 |
| 每天上班 | **数据总览** | 扫一眼 6 个统计卡，重点：待确认签单、今日敏感查看、即将失效。 |
| 每天 | **房源管理** | 处理"待维护房源"：到期该核验的点"电话核验"；有"待审核"的顺手审。 |
| 每天 | **签单审核** | "待管理员确认"的签单核实后尽快确认——不确认中介拿不到分佣记录。 |
| 每天 | **带看审核** | 审当天的水印照，真实的尽快通过（额度当天才生效，拖到第二天就没意义了）。 |
| 每天下班前 | **数据备份** | 点一次"导出 JSON 备份"。 |
| 每周 | 房源管理 → **坐标待修正** | 把带 ⚠ 的房源逐套做坐标修正。 |
| 每周 | **废房源池** | 过一遍下架房源，还在租的联系上传人核实后重新上架。 |
| 每周 | **敏感查看足迹** | 抽查异常：某人短期集中查看大量房源电话要留意跳单风险。 |
| 按需 | **飞书同步 / 上线检查** | 公司房源有更新时手动同步；版本更新后跑一遍上线检查。 |

## 20. 管理员常见处理场景速查

| 场景 | 到哪里、怎么处理 |
| --- | --- |
| 有人说注册了登录不了 | **账号管理 → 注册审核**：找到他的申请，核实身份后点"通过为中介/员工"，然后通知他用注册时的手机号+密码登录。 |
| 中介忘记密码 / 老账号没密码 | **账号管理** → 中介/员工行点**"设置/重置密码"**，输入至少 8 位初始密码，转告本人，提醒他登录后自己改。 |
| 中介说"账号尚未设置登录密码" | 同上，给他设一个初始密码。 |
| 要开通新中介但他还没注册 | 两条路：让他在小程序提交注册申请后你审核通过；或你直接在**账号管理**建"中介账号"（姓名+手机号+初始密码）。 |
| 中介离职/终止合作 | **账号管理** → 中介/员工行点**"删除"**（软删，历史数据保留，此后无法登录）。 |
| 后台同事离职 | **账号管理** → 管理员行点**"禁用"**或**"删除"**。 |
| 中介说签单了，佣金没到 | **签单审核** → 核对成交金额后点**"确认签单"**，确认后才生成分佣。 |
| 要调整分佣比例 | **房源管理**顶部**"分佣配置"**（仅超管）→ 改比例 → "保存分佣配置"。只影响新签单，存量按签单时快照。 |
| 业主房源上传后中介看不到 | **房源审核**（或房源管理里"待审核"房源）→ 核对信息后**"审核通过"**上架。 |
| 房源在地图上找不到/位置不对 | **房源管理** → 该房源点**"坐标修正"** → 地图点选真实位置 → "确认坐标"。 |
| 中介带看了想加查看额度 | **带看审核** → 核验水印照真实后点**"通过"**，其当天普通额度 +1。 |
| 房源第 7 天自动下架了要恢复 | **废房源池** → 核对房态后点**"重新上架"**。 |
| 中介电话确认点错、房源被下架 | 同上，从**废房源池**重新上架。 |
| 要手动下架某套房源 | **房源管理** → "编辑" → 状态改为"已下架"保存，移入资产池。 |
| 想开启/关闭第 3、5 天核验提醒 | **房源管理**顶部"上传房源电话核验规则"开关 → "保存规则开关"（第 7 天失效不受开关影响）。 |
| 怀疑跳单、要查谁看了房东电话 | **敏感查看足迹**，按查看人/房源/时间核查。 |
| 找房助手推荐不准 | **客服反馈**看反馈 → **客服Trace**复盘 → 典型坏例"加入评估"。 |
| 公司房源要更新 | **飞书同步** → "立即同步"（不确定先"预演同步"）。 |
| 例行数据保护 | **数据备份** → 上线前 / 批量导入前 / 每日下班前各"导出 JSON 备份"一次。 |
| 普通管理员说看不到账号管理/系统配置 | 正常：系统配置整组仅超级管理员可见。需要权限找超管把其账号权限改为"全部后台权限"（或由超管代为操作）。 |
