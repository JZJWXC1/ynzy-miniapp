## 一、文档目的

本文件只用于 Yooni 找房助手的开工、交接、审计、返修和验收记录。目标是让主开发、审核裁判和用户能快速回答四个问题：

1. 当前正在做什么。
2. 谁负责开发、谁负责审核。
3. 哪些结论已经用可重复证据验证。
4. 下一步需要谁做什么。

## 二、模块边界

### 纳入本文件

- 找房意图识别、需求解析、追问与多轮上下文。
- 房源匹配、硬条件校验、排序、推荐理由与诚实无房。
- 地点解析、半径检索及 Yooni 使用的坐标兜底。
- Yooni 对话页及语音转文字入口，但文字找房必须能独立工作。
- Yooni 专用离线评测、线上反馈指标和相关安全边界。

## 五、不可偏离的产品原则

1. **精确优先。** 硬条件不满足时不得标成符合，不得静默放宽后冒充精确推荐。
2. **诚实处理能力缺口。** 地点、学区、通勤或房态无法确认时，优先精准追问或明确告知暂不支持。
3. **文字链路独立。** 文字找房不得依赖录音器、ASR WebSocket 或语音回调状态。
4. **平台词条优先。** 用户询问已配置板块、区域或小区时直接筛选；相近词先确认，完全未知时使用平台真实范围能力兜底。
5. **不编造事实。** 不编造房源、小区、坐标、特征、房态或距离。

## 六、指标定义

旧文档中的“20 条种子、97.5% 满意率”属于受控合成场景离线分数，不能称为真实用户满意率，也不能直接证明线上产品变好。

### 1. 离线场景合规分

用于代码回归，不作为北极星指标。

- 分母必须是冻结版本的同一批用例；增删用例后建立新版本，不与旧百分比直接比较。
- 同时报告总用例数、各类别数量、满分/半分/零分和“违反硬条件”数量。
- 只有在同一评测集上重跑变更前后版本，才能声称分数提升。
- 合成库、脱敏真实需求和生产在线数据必须分别标注。

### 2. 推荐精确率

`满足全部硬条件的推荐房源数 / 实际返回的推荐房源数`。

该指标约束“不撒谎”，但单独使用会奖励少推荐或不推荐，因此不能独立作为北极星。

### 3. 有效推荐覆盖率

`至少获得 1 套精确匹配房源的、条件完整且属于当前能力范围的需求数 / 同类需求总数`。

该指标约束“不能只靠诚实无房拿高分”。报告时必须同时展示推荐精确率。

### 4. 在线有用率（候选北极星，待用户拍板）

`获得明确“有用”反馈的有效找房会话数 / 获得反馈的有效找房会话数`。

线上反馈尚未形成稳定样本前，只报告“待建立”，不得用离线合规分替代。最终北极星及统计窗口由用户确认。
