# V1 最终合并审计门槛

合并前必须在合并工作树根目录执行：

```bash
node server/scripts/v1-final-audit.js
git diff --check
git diff --name-only
```

## 自动化审计项

`server/scripts/v1-final-audit.js` 会检查以下门槛：

- `app.json` 和 `custom-tab-bar/index.js` 的底部导航固定为：找房、房源、地图、我的。
- `server/scripts/smoke-test.js` 没有未提交或已暂存改动。
- `server/scripts/map-v1-test.js`、`server/scripts/assistant-v1-test.js`、`server/scripts/backend-contract-v1-test.js` 均存在。
- 第一版可见入口不暴露房源群、积分、充值、换群、微信支付等历史入口关键词。
- 报备、签单、后台确认签单接口存在，并保留固定 20% 分佣、金额按分计算的后端契约。
- 地图、找房助手、后端契约三条 V1 脚本可直接运行。

## 历史代码边界

第一版隐藏房源群、积分、充值、换群、微信支付，但不删除后端历史代码。最终审计脚本只检查第一版可见入口和 V1 契约，不把保留的历史模块源码视为失败项。

如后续恢复任何历史入口，必须先更新第一版产品规则和验收清单，再同步调整本审计脚本。

## 合并前人工复核

- 确认 `git diff --name-only` 只包含本次任务允许的新增文件。
- 确认没有修改 `pages`、`utils`、`server/src`、`admin-web`、`server/scripts/smoke-test.js`。
- 确认管理员后台的报备、签单、确认签单接口已由后端提供；若前端后台入口另有任务接入，应在对应任务内完成，不在本卫生任务中越界修改。
- 确认上线环境密钥不在仓库内，微信支付、OSS、LLM 等环境变量只通过部署环境配置。

## 微信开发者工具验收步骤

1. 编译后确认底部导航只有找房、房源、地图、我的。
2. 上传房源时不传视频应被拦截，带视频后可提交。
3. 找房助手输入不完整需求时应追问，输入完整需求后先展示确认字段，再匹配房源。
4. 地图页只展示真实且已确认的小区坐标，并显示小区套数；无可靠坐标的房源不能进入地图。
5. 房源详情页先提交报备，客户手机号为空时应拦截。
6. 报备成功后从报备记录发起签单，只填写成交月租、房东实际支付佣金和可选备注。
7. 管理员确认签单后再生成正式分佣记录，上传人分佣为房东实付佣金的 20%。
8. 前台列表、详情、匹配、地图不展示完整楼栋、单元、房号、房东电话或上传人手机号。
